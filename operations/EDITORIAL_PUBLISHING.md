# Editorial publishing

Published content has one source: editorial/published.json. HTML, RSS, public route allowlist and static sitemap are generated by operations/build-editorial.mjs. No database or paid API is required.

## Workflow

1. Draft and review privately outside the public repository and Cloudflare web root. Never commit unpublished manuscript text, credentials or embargoed content. The public repository is not a private CMS.
2. Approve the article and add a published entry to editorial/published.json. Supply a unique slug, title, description, category, actual publication date, structured blocks (heading, paragraph or internal links), and related links. Plain text is escaped; arbitrary HTML is not accepted.
3. Run node operations/build-editorial.mjs, then node tests/editorial-build.mjs and the existing regression suite. Commit generated output with its source to development. CI rejects stale output.
4. Check Cloudflare Preview, security and regression results. Production requires separate owner approval.
5. To unpublish, replace the entry with only slug and status unpublished (or remove it), regenerate, and review deleted HTML, sitemap, RSS and related links. A removed URL is no longer in the public allowlist; previously published text can remain in Git history and external caches. Do not treat unpublishing as confidential erasure.

The owner can ask ChatGPT/Codex to perform this workflow without a terminal. This is a repository-managed publication, not an authenticated browser CMS or email newsletter service. Private editorial dashboard and research-data pipelines are separate future work. Keep research grounded in dated samples and methodology.
