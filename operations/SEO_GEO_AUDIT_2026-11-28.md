## Technical SEO and landing-page coverage

- Exact sitemap reconciliation produced 10 roots, utilities and indexes, 100 studio profiles, nine studio-city directory pages, six articles and ten discipline pages. The checked-in sitemap, live Production sitemap and live Preview sitemap had identical URL sets. At release `13f475a`, the checked-in set had 136 URLs and included the withdrawn editorial. The static generators and dynamic D1 queries are both useful. Their overlapping URL definitions create drift risk and a required regression check. Dynamic errors in either eligibility query currently return 503 for the whole sitemap. The sitemap endpoint is uncached, and the employer URL `lastmod` uses `datePosted`; treat that as incomplete for substantive updates. [Previous static sitemap](https://github.com/zedwontmiss/studio-openings/blob/13f475a/sitemap.xml), [dynamic sitemap](../functions/sitemap.xml.js#L9-L38), [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- All 135 sitemap URLs had unique titles, OG titles and Twitter card tags. There were 134 descriptions, with `/privacy` the exception. All 135 lacked `og:image`. Privacy still had a visible H1 and body text. The homepage emits `WebSite` with publisher Organization and six articles emit `Article`; JSON-LD parsed. No individual studio/location schema or JobPosting appeared in the audited live sitemap pages. No schema validator accepted or rejected a live job because none was available. [Studio profile generator](build-studio-profiles.mjs), [editorial generator](build-editorial.mjs), [Google structured data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)
- JobPosting code requires approved paid employer publication, verified geographic and applicant scope, expiry and an apply route. The source detail route has a stronger rights/freshness gate and emits no JobPosting. Labor disclosure and application options in fixture tests are functional. Compare the complete visible job description and employer original posting date before releasing JobPosting: the current generator caps the description and derives `datePosted` from submission creation time. Google requests the original posting date and complete job details, with appropriate city/country and remote eligibility. A length check cannot establish completeness. Only use schema on a single valid, directly accessible job with an application path. The shared expiry gate returns 404 for unavailable employer/source jobs, removes sitemap membership, and prevents active publishing elsewhere. [Employer SEO policy](../lib/seo-jobs.js#L8-L55), [source SEO policy](../lib/source-seo-policy.js), [Google JobPosting and closure guidance](https://developers.google.com/search/docs/appearance/structured-data/job-posting)
- The ten discipline pages provide server-rendered editorial context and link to Jobs filters. The homepage exposes 270 discipline-country links to canonical-home query routes. The three Product Design Canada word orders and labels produced the same five visible rows in this Chromium sample, and the browse link used the same compact query. Other term matching is token-based and raw phrase order can affect ranking for unstructured relevance queries. Combined country/discipline, software, remote and specialized studio pages need a verified inventory and demand gate. Three other example searches, Architecture London, Revit Australia and Remote Interior Design, were empty in this sample. Zero display results here are insufficient to estimate the size of any market. [Country/query matcher](../assets/app.js#L617-L688), [discipline route](../functions/disciplines/%5Bslug%5D.js), [filter URL parser](../assets/filter-links.js)
- Nine verified-office studio city guides already exercise a useful static model. Broader city job directories are Preview-only, including London, and noindex. Meaningful regional/combined job landing pages are absent in usable Production routes tested. Canonicalize facets to their existing home/search destination unless eligibility supports a standalone page. Test coverage, distinct value, active vacancies and matching filters before enabling any pilot. [Studio location generation](build-studio-locations.mjs), [Preview city gate](../functions/%5Bcity%5D.js), [Google spam and doorway policy](https://developers.google.com/search/docs/essentials/spam-policies)

## GEO and crawler policy

Production robots.txt allowed all crawlers and advertised one sitemap. The root and robots file returned 200 for ordinary requests and the sampled Googlebot, Bingbot, OAI-SearchBot, GPTBot, ChatGPT-User, PerplexityBot and Perplexity-User user-agent strings. These were local synthetic headers, with no verified crawler IP or WAF/Bot Management log evidence. A synthetic Bravebot string also returned 200. Brave documents no distinct UA and says Googlebot crawlability governs its own crawler. Cloudflare may enforce controls separately from robots, so SaaS provider acceptance remains an access-dependent check. [Live robots.txt](https://s-o.app/robots.txt), [Brave crawler](https://safe.search.brave.com/help/brave-search-crawler), [Bing crawlers](https://www.bing.com/webmasters/help/which-crawlers-does-bing-use-8c184ec0)

| Platform | Documented controls and consequences |
| --- | --- |
| ChatGPT | `OAI-SearchBot` supports search. `GPTBot` is training-related. `ChatGPT-User` is user-triggered and may have different robots behavior. Choose training preference independently, then verify authenticated bot traffic where feasible. [OpenAI crawler docs](https://developers.openai.com/api/docs/bots) |
| Google and Gemini | Google Search crawlability and indexability govern Search AI features. Google-Extended is a separate product token covering designated Gemini training and grounding uses. Google documents separate Search generative AI controls where available. [Google AI search guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [Google-Extended](https://developers.google.com/crawling/docs/google-extended) |
| Perplexity | `PerplexityBot` supports search discovery. `Perplexity-User` fetches in response to user requests. Verify published IP ranges when diagnosing edge rules. [Perplexity crawler docs](https://docs.perplexity.ai/docs/resources/perplexity-crawlers) |
| Bing and Copilot | Keep canonical pages discoverable to Bingbot and use Bing Webmaster Tools for crawl/index and AI Performance where available. A citation and a referred session measure different outcomes. [Bing guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a), [AI Performance](https://www.bing.com/webmasters/help/?topicid=9f8e7d6c) |
| llms.txt | The requested path returned noindex homepage HTML with 200 via fallback. No actual convention file was present. Fix the route status with other unknown URLs. Google explicitly disclaims a need for this file. Consider an experiment only with a defined consuming client and evidence target. [Google AI optimization guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) |

The strongest citation assets would be stable studio profiles with verified source links and office identifiers, substantive original articles, and dated aggregate insights with eligible population, source mix, coverage, exclusions and sample size. Connect jobs to studios only when the current evidence match succeeds. Include correction dates and canonical IDs in visible HTML and supported machine-readable fields. Preserve public facts and rights while leaving private operator notes out of the public site. Track Search Console visibility separately from Bing AI citations, confirmed crawler traffic, reproducible sample observations and referred traffic. The effects of markup, robots changes or new content on recommendations remain to be measured.
